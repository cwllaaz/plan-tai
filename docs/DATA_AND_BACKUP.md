# 计划台 V1.0 · 数据库与备份说明

## 1. 数据库位置

| 场景 | 路径 |
|---|---|
| 正式运行（默认） | `%APPDATA%\计划台\data\app.db` |
| 便携 / 测试覆盖 | 环境变量 `JIHUATAI_DATA_DIR` 指定的目录下的 `data\app.db` |
| 演示模式 | 内存，不落盘（`JIHUATAI_DEMO=1`） |

`%APPDATA%` 通常是 `C:\Users\<用户名>\AppData\Roaming`。

- 首次启动自动创建目录与数据库；不需要手动建库。
- 数据库使用 WAL 模式，运行时同目录会出现 `app.db-wal` / `app.db-shm`，属于正常现象；
  正常关闭时会执行 checkpoint。
- 程序**不会**在数据库损坏时静默重建（避免抹掉真实数据），会给出可读错误并保留文件。
- 安装目录、工作目录、临时目录都**不会**写数据；升级或重装应用不会丢数据。

## 2. 表结构概览

- `projects`：项目（名称、颜色、状态、排序）。
- `plan_spans`：跨天阶段（项目、起止日、状态）。
- `planner_tasks`：任务（项目/阶段、日期、时刻、优先级、完成态）。
- `daily_notes`：每日备注（按日期唯一）。
- `change_log`：变更日志（V1 只写不读，为后续同步预留）。
- `settings`：结构版本等键值。

软删除：删除只写 `deleted_at`，记录保留；列表与月历默认过滤。
删除项目会级联软删除其阶段与任务；删除阶段只解绑任务（任务保留）。

## 3. 备份格式

JSON，顶层形状：

```json
{
  "format": "jihuatai.backup",
  "schemaVersion": 1,
  "appVersion": "1.0.0",
  "exportedAt": "2026-11-15T...",
  "projects": [],
  "planSpans": [],
  "plannerTasks": [],
  "dailyNotes": []
}
```

- 不含日志、设备 ID、绝对路径。
- 备份目录：`%APPDATA%\计划台\data\backups\`。
- 文件名：`jihuatai-backup-YYYYMMDD-HHmmss-xxxx.json`。

## 4. 恢复流程（安全设计）

1. 读取并校验 JSON 结构与 `schemaVersion`；高于当前版本直接拒绝并提示升级。
2. 校验引用完整性（任务的项目/阶段必须同属且存在）。
3. 自动对当前数据做 SQLite 一致快照：`pre-restore-*.db`。
4. 单事务内整体替换四张表；任何一步失败整体回滚。
5. 回读比对校验，成功后通知所有界面流刷新。

因此：**恢复失败不会破坏现有数据**；恢复成功后旧数据仍可在快照中找回。

## 5. 迁移策略

- `schema_version` 从 1 开始；只做向后兼容迁移（加表/加列/加索引）。
- 升级前先备份；迁移失败保留原库并提示，不自动删库。

## 6. 排障

| 现象 | 处理 |
|---|---|
| 启动提示「无法创建本地数据目录」 | 检查 `%APPDATA%` 写权限/磁盘空间 |
| 启动提示「无法打开本地数据库文件」 | 检查文件是否被其他程序占用；确认不是只读 |
| 启动提示「结构版本高于当前应用」 | 使用更新版本的应用打开，勿降级覆盖 |
| 想重置为全新环境 | 先备份，再关闭应用，重命名 `app.db` 后重启（程序会建新库） |
