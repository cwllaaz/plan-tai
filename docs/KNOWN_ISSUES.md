## 3. 环境与验证限制

1. **本机验证沙箱**：从 Agent 终端直接 `Start-Process` / 资源管理器 / COM 启动 exe 时，
   进程被限制为只能写工作区，导致 `%APPDATA%` 建库失败（应用正确显示了错误页）。
   通过 WMI 在沙箱外启动后，默认路径建库、重启持久化均正常。
   这是验证环境限制，不是面向最终用户的行为；普通双击启动不受影响。
2. 由于沙箱对鼠标坐标注入不稳定，**项目页与备份恢复对话框未采集真实鼠标端到端截图**：
   - 项目 CRUD / 阶段 CRUD：`test/app/integration_flow_test.dart` 覆盖。
   - 备份导出 / 恢复 / 回滚：`test/app/backup_persistence_test.dart` 覆盖服务层。
3. 验证机为 150% 缩放、1920×1080 级别屏幕；真实 1366×768 物理分辨率未单独跑，
   已用 1100×700（窗口最小尺寸）等价验证 7 列不横向滚动。
4. 未在干净虚拟机做"安装 → 卸载 → 重装"验证。

## 4. 数据层风险

1. 数据库为 WAL 模式：**不要直接复制运行中的 `app.db`** 做迁移；请用应用内备份/恢复。
   手动替换 db 文件（尤其来自其他 SQLite 运行时创建的文件）可能出现
   `PRAGMA synchronous` 阶段的 CANTOPEN；V1 不承诺跨工具搬运 db 文件。
2. 备份恢复是整体替换，不做增量合并；多人/多机并行编辑不在 V1 范围。
3. `change_log` 只写不读，为 V2 同步预留，尚未验证长时间增长后的清理策略。
