# 计划台 Android · 数据与同步说明

> 面向使用者与后续维护者：Android 版的数据存在哪里、如何备份、云端如何同步、出问题如何恢复。
> 协议与接口的权威文档：`docs/sync/*`、`docs/DATA_CONTRACT.md`、`docs/MODULE_API.md`。

---

## 1. 数据在哪里

| 数据 | 位置（Android 应用私有目录） | 说明 |
|---|---|---|
| 业务数据库 | `/data/user/0/com.jihuatai.planner/files/data/app.db` | SQLite（WAL），项目/跨天阶段/任务/每日备注/设置 |
| 账号工作区库 | `.../files/data/accounts/<ownerId>/app.db` | 与桌面一致：绑定账号后使用独立工作区，避免账号串号 |
| 工作区指针 | `.../files/data/cloud_workspace.json` | 只含 ownerId + 数据库相对路径，不含令牌/密码 |
| 本地备份 | `.../files/data/backups/*.json` | 与 Windows 完全同一 JSON 格式（`format=jihuatai.backup`） |
| 登录令牌 | Android Keystore 加密后存 SharedPreferences 密文 | 无明文；应用已关闭系统自动备份（`allowBackup=false`）。个人日程数据默认不会进入系统云备份 |
| 同步队列/游标/冲突 | 同一个 `app.db` 内的 `sync_outbox` / `sync_state` / `sync_conflicts` | 与本地写入同事务，进程被杀不丢 |

**卸载应用会删除上述全部数据**（Android 机制）；覆盖安装（升级）会保留。

---

## 2. 本地优先原则

1. 任何操作先写本地 SQLite，成功后界面立即更新；云端是可选的附加能力。
2. 未登录、断网、服务器故障时：查看、新建、修改、完成、删除、备注、项目管理全部可用。
3. 登录后：本地写入进入 `sync_outbox`（同事务），由同步引擎按顺序上传；云端增量变更通过游标拉取。
4. **不允许**用云端全量数据覆盖本地作为常规同步；「覆盖下载」是独立按钮 + 二次确认 + 先备份。
5. 冲突（两端改同一记录）不会静默覆盖：写入 `sync_conflicts`，界面提示「需要处理」，用户可选保留本机/使用云端；两端版本都保留在冲突记录里。

## 3. 首次登录与数据归属

| 本机情况 | 云端情况 | 应用行为 |
|---|---|---|
| 无数据 | 无数据 | 直接绑定，可正常同步 |
| 有数据 | 无数据 | 提示「上传本机到账号」，确认后上传，本机数据不丢 |
| 无数据 | 有数据 | 提示「以云端为准」，为账号新建独立工作区，**重启后全量下载** |
| 两端都有数据 | | 必须用户选择；不会自动上传或覆盖 |
| 本机已绑定其它账号 | | 提示不能上传到当前账号（`boundOtherAccount`），需按引导处理 |

账号与同步页面同时展示：当前账号、服务器、连接状态、待同步数量、上次成功同步时间、失败原因、自动同步开关、立即同步/上传/下载、退出账号、冲突处理入口。

## 4. 自动同步策略（首版）

| 触发 | 说明 |
|---|---|
| 登录成功 / 会话恢复 / 应用启动 | 延迟约 1.5s 触发一次 |
| 从后台回到前台 | 15s 节流；有待同步或距上次成功 ≥2min 才联网 |
| 保存任务后 | 引擎本地写入 debounce（默认自动上传开启，约 2s） |
| 离线且有待同步 | 30s→5min 指数退避重试 |
| 应用被彻底关闭 | 不同步；下次打开继续（outbox 在 SQLite，不依赖内存） |

## 5. 备份、导出与恢复

- 应用内「我的 → 数据与备份」：创建本地备份（JSON，写在私有目录）、从本地备份恢复；
- **导出备份到文件**：系统「保存到…」选择下载/网盘位置（SAF，不申请存储权限）；
- **从文件导入并恢复**：系统文件选择器 → 完整校验（格式/版本/跨表引用/重复 ID）→ 显示摘要与覆盖风险 → 二次确认 → 恢复；恢复前自动生成 pre-restore 快照；
- 导出的 JSON 与 Windows 版**逐字段相同**，两端可互相导入；
- 恢复是「整体替换」语义，不是合并；常规两设备同步请用「登录 + 同步」，不要用备份覆盖。

## 6. 故障处理

| 现象 | 处理 |
|---|---|
| 登录提示「安全存储不可用」 | 设备 Keystore 异常：应用保持纯离线（不保存明文令牌）；重启设备/系统更新后重试 |
| 长期「离线」 | 检查网络与服务器地址（正式环境必须 https；本机调试仅允许 localhost/127.0.0.1 的 http） |
| 「需要处理」冲突 | 进入账号页 → 冲突列表，逐条选择保留本机/使用云端 |
| 数据库损坏提示 | 应用会停止并提示，不会重建；从「数据与备份」导入最近备份恢复 |
| 换机迁移 | 旧机导出 JSON 备份 → 新机安装后用「从文件导入并恢复」，或直接登录账号同步 |
